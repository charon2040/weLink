# WeLink 前后端逻辑文档（非消息部分）

## 1. 文档范围

本文档只覆盖非消息业务链路：

- 注册、登录、refresh token
- JWT 与内部接口鉴权
- 前端请求封装与状态管理
- WebSocket 建连、心跳、重连
- 好友、群组、文件上传
- 管理与运维接口

消息持久化、outbox、群聊扩散、历史/离线消息请看 `document/消息链路文档.md`。

## 2. 总体架构

WeLink 前端是 Vue 3 SPA，后端是一个 Spring Boot 进程同时暴露：

- HTTP REST：`8080`
- Netty WebSocket：`8081`

依赖中间件：

- MySQL / ShardingSphere
- Redis
- Kafka
- MinIO

开发期接口关系：

- Axios `baseURL` 为 `/api/v1`
- Vite 将 `/api` 反代到 `http://localhost:8080`
- WebSocket 当前前端默认连 `ws://localhost:8081/ws`

注意：这个 WebSocket 地址目前仍是本地开发硬编码，不是生产级多实例入口方案。

## 3. 用户认证链路

### 3.1 注册

前端调用：

```text
POST /api/v1/auth/register
```

后端入口：

- `AuthController.register`
- `UserService.register`

行为：

- 校验用户名是否重复
- 用 BCrypt 加密密码
- 默认昵称回填为用户名
- 写入 `user` 表

注册成功只返回成功状态，不自动登录。

### 3.2 登录

前端调用：

```text
POST /api/v1/auth/login
```

后端返回：

- `accessToken`
- `refreshToken`
- `userInfo`

前端在 `stores/user.js` 中会：

- 保存 `token`
- 保存 `refreshToken`
- 保存 `userInfo`
- 登录成功后立刻调用 `wsService.connect(accessToken)` 建立长连接

### 3.3 refresh token

当前 refresh 已实现，不再是占位能力。

前端调用：

```text
POST /api/v1/auth/refresh
```

后端入口：

- `AuthController.refresh`
- `UserService.refresh`

前端 `utils/request.js` 当前实现了单飞 refresh：

- 收到 `401 / 1004 / 1005` 时触发刷新
- 同一时刻只发 1 次 `/auth/refresh`
- 其他失败请求等待同一个 Promise
- refresh 成功后自动重放原请求
- refresh 失败后清理登录态并跳回登录页

### 3.4 JWT 与内部接口鉴权

`WebMvcConfig` 中当前的用户级 JWT 放行路径为：

- `/api/v1/auth/register`
- `/api/v1/auth/login`
- `/api/v1/auth/refresh`
- `/api/v1/files/**`

内部接口共享密钥拦截范围为：

- `/internal/**`
- `/admin/**`
- `/drain`

这些接口要求请求头：

```text
X-Internal-Secret
```

## 4. 前端工程

前端当前主要结构：

```text
frontend/src/
├─ api/              REST API 封装
├─ router/           Vue Router
├─ stores/           Pinia 状态
├─ utils/request.js  Axios 封装
├─ utils/websocket.js WebSocket 客户端
├─ views/            页面
└─ main.js
```

### 4.1 Axios 封装

后端统一返回：

```json
{ "code": 200, "message": "success", "data": ... }
```

所以前端当前约定是：

- 先看 `res.code`，不是 HTTP status
- `code !== 200` 时统一由拦截器处理错误提示
- 未授权场景走 refresh token 链路

### 4.2 Pinia 状态

- `user`：保存 token、refreshToken、userInfo、登录退出逻辑
- `contact`：保存好友、群组、待处理申请
- `chat`：保存会话、消息、历史分页、未读数和文件元数据缓存

## 5. WebSocket 接入与重连

当前前端逻辑：

1. 登录成功后建立 WebSocket 连接
2. `onopen` 后发送 `auth` 帧
3. 每 30 秒发送一次 `heartbeat`
4. 收到消息后自动回 `ack`
5. 断开后最多重连 5 次

当前实现限制：

- `WS_URL` 仍硬编码为 `ws://localhost:8081/ws`
- 更适合本地开发，不适合直接复用到多实例生产入口
- 如果后续要上 LB/域名/WSS，应改成环境变量或按 `window.location` 推导

## 6. 好友与群组

### 6.1 好友

当前已覆盖：

- 发起好友申请
- 按用户名发起申请
- 接受/拒绝申请
- 查询好友列表
- 查询待处理申请
- 删除好友

### 6.2 群组

当前已覆盖：

- 创建群
- 按群 ID 入群
- 按群名/群号入群
- 获取群信息
- 获取群成员
- 更新群公告
- 邀请成员
- 按用户名邀请成员
- 踢人
- 转让群主
- 退群
- 解散群

## 7. 文件上传

文件上传链路：

1. 前端调 `/api/v1/file/upload`
2. 后端上传对象到 MinIO
3. 返回 `fileId`、下载 URL、元信息
4. 前端消息体保存 `fileId`，展示时再调 `/api/v1/files/{fileId}/meta`

`/api/v1/files/**` 当前放行 JWT，原因是图片/文件链接需要支持直接访问。

## 8. 管理与运维接口

当前主要管理接口包括：

- `/actuator/health`
- `/actuator/prometheus`
- `/admin/degradation/level/{0..5}`
- `/admin/outbox/*`
- `/drain`

注意：

- `/drain` 受 `X-Internal-Secret` 保护
- 当前 `k8s/deployment.yaml` 的 preStop 仍未带这个 header，模板与现状不一致，不能直接视为已可用的优雅摘流方案

## 9. 当前限制与结论

- 非消息业务链路整体已经可用，refresh token 也已落地
- 前端 WebSocket 地址仍是开发态硬编码
- K8s 模板中的内部鉴权与默认分片模式尚未和当前实现完全对齐
- 这些问题不影响本地开发与联调，但限制了“直接拿模板上生产”的可信度

- 后端消息链路已完成第5轮批量优化，消息持久化吞吐从 ~300条/s 提升至 ~10,000条/s
- 详细参见 `document/消息链路文档.md` 第5.3节和 `document/私聊群聊改造总结.md` 第5节
