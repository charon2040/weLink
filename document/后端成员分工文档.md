## 2. 分工说明

后端+前端按 3 名成员进行分工，每人负责独立业务域，工作量大致均衡：

- **charon2040**：公共基础设施 + 用户认证 + 网关鉴权 + 消息数据层 + 部署配置 + 前端认证与框架
- **DevilVoice (lyk_whu)**：好友关系群组 + 消息业务逻辑 + 前端联系人
- **成员C**：实时通信 + 可靠投递 + 前端聊天与WebSocket

分工原则：
- 按业务域划分，每人有清晰的模块边界
- charon2040 负责项目骨架、公共能力、认证鉴权和消息数据模型（entity/DTO/mapper），代码量偏少但包含大量配置/SQL/部署文件
- DevilVoice 负责社交关系域和消息业务逻辑（service/controller），是核心业务实现
- 成员C 负责在线链路、异步可靠投递和聊天前端，是实时性核心

## 7. 协作接口与规则

### 跨成员协作接口

| 接口 | 涉及成员 | 说明 |
|------|---------|------|
| 消息落库 → 实时投递 | DevilVoice ↔ 成员C | MessageService 写库后进入 IM 投递链路 |
| 投递回执 → inbox 状态 | 成员C → DevilVoice | 投递成功后推进 inbox 状态 |
| Socket 鉴权 → JWT 校验 | 成员C ↔ charon2040 | IM 鉴权依赖 JWT 令牌校验 |
| 群组创建 → 消息投递 | DevilVoice ↔ 成员C | 群组变更需通知 IM 层 |
| 前端 chat store → message API | 成员C → DevilVoice | chat.js 调用 messageApi 拉取历史 |
| 前端 API 定义 → 后端接口 | charon2040 → 全员 | api/index.js 定义所有接口路径 |

### 协作规则

- 涉及 `common`、`gateway`、`application.properties`、`pom.xml` 的改动，默认先同步 charon2040
- 涉及 `MessageService.java` 与 `IMService.java` 联动的改动，DevilVoice 和成员C 必须共同评审
- 涉及群成员读游标 `lastReadSeq`、群消息序号 `groupSeq` 的改动，DevilVoice 和成员C 必须共同确认
- 涉及登录态、JWT、请求鉴权的改动，charon2040 和成员C 必须共同确认
- 涉及 `api/index.js` 新增接口的改动，需通知对应后端负责人确认路径一致
- 新增测试时，优先由对应模块负责人补充，不跨模块随意修改对方测试
