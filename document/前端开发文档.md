# WeLink 前端开发文档

## 1. 技术栈

当前前端采用：

- Vue 3
- Vite
- Pinia
- Vue Router
- Element Plus
- Axios
- 原生 WebSocket

## 2. 目录结构

```text
frontend/src/
├─ api/              后端 API 封装
├─ router/           前端路由
├─ stores/           Pinia 状态
├─ utils/request.js  Axios 封装
├─ utils/websocket.js WebSocket 客户端
├─ views/            页面
├─ App.vue
└─ main.js
```

## 3. REST API 封装

`frontend/src/api/index.js` 当前分成 5 组：

- `authApi`
- `friendApi`
- `groupApi`
- `messageApi`
- `fileApi`

已经覆盖的重要接口包括：

- `/auth/register`
- `/auth/login`
- `/auth/refresh`
- `/auth/user/search`
- `/friend/requests/pending`
- `/group/join/by-no`
- `/message/offline`
- `/message/sync`
- `/file/upload`

## 4. Axios 约定

后端统一返回：

```json
{ "code": 200, "message": "OK", "data": ... }
```

所以前端在 `utils/request.js` 中：

- 统一从 `res.code` 判断成功失败
- 对 `401/1004/1005` 做 refresh token 单飞重试
- refresh 失败后清理登录态并跳回登录页

## 5. WebSocket 约定

默认地址：

```text
ws://localhost:8081/ws
```

客户端发送的主要帧类型：

- `auth`
- `message`
- `ack`
- `heartbeat`
- `recall`

当前前端行为：

- 连接成功后立即发送 `auth`
- 每 30 秒发送一次 `heartbeat`
- 收到消息后自动发送 `ack`
- 断线后自动重连，最多 5 次

## 6. Pinia 状态

### 6.1 `user`

负责：

- token / refreshToken
- 当前用户资料
- 登录、退出与本地持久化

### 6.2 `contact`

负责：

- 好友列表
- 群列表
- 申请列表

### 6.3 `chat`

负责：

- 会话列表
- 当前会话
- 消息列表
- 历史分页
- 未读数维护
- 文件元数据缓存

## 7. 开发启动

```bash
cd g:/WeLink/frontend
npm install
npm run dev
```

默认联调假设：

- HTTP API: `http://localhost:8080`
- WebSocket: `ws://localhost:8081/ws`

## 8. 开发注意事项

- 不要按 HTTP status 判断业务成功，先看 `code`
- WebSocket 消息需要兼容私聊和群聊两种 cursor 更新逻辑
- 新增接口时优先补在 `api/index.js`，不要把裸 axios 调用散落到页面
- 会话已读走 `/message/read/conversation`，不要只更新前端未读角标
