# WeLink 即时通讯系统 — 需求规约

## 1 引言

### 1.1 项目背景

WeLink 是一款面向企业场景的高并发分布式即时通讯系统，需支撑万人级在线用户、万级消息吞吐量，并保证消息投递的可靠性。系统采用 WebSocket 长连接实现实时消息推送，通过 Kafka 异步消息队列解耦消息收发与持久化，使用 MySQL 分库分表存储海量消息数据。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| 写扩散 (Write Diffusion) | 群消息发送时，为每个在线成员直接推送，同时写入每个成员的 inbox |
| 读扩散 (Read Diffusion) | 大群消息发送时，仅写入群消息表，由各实例消费者拉取并推送给本地在线用户 |
| Ingress | 消息入口，指客户端发送的消息经 Kafka Topic 进入服务端处理流程 |
| Outbox | 发件箱模式，用于跨实例消息投递的可靠发布，配合 Pending 索引表实现重试 |
| E2E 延迟 | 端到端延迟，从发送者发出消息到接收者收到消息的完整时间 |
| 扇出 (Fan-out) | 一条群消息需要推送给 N 个成员的过程 |

- Netty 4.x WebSocket 实现

## 2 功能需求

### FR-01 用户注册与认证

**描述**：用户通过用户名和密码注册账号，登录后获取 JWT Token 对（AccessToken + RefreshToken）。

**功能点**：
- FR-01.1 用户注册：提交用户名和密码，系统校验用户名唯一性后创建账号
- FR-01.2 用户登录：验证用户名密码，返回 AccessToken（2h 有效）和 RefreshToken（7d 有效）
- FR-01.3 Token 刷新：使用 RefreshToken 换取新的 AccessToken
- FR-01.4 用户查询：按用户名搜索用户，按 ID 获取用户信息

**接口**：
- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `GET /api/v1/auth/user/search?username=`
- `GET /api/v1/auth/user/{userId}`

### FR-02 私聊消息

**描述**：两个用户之间进行一对一实时消息通信。

**功能点**：
- FR-02.1 发送私聊消息：支持文本（msgType=1）、图片（msgType=2）、文件（msgType=3）等消息类型
- FR-02.2 接收私聊消息：在线用户通过 WebSocket 实时接收，离线用户上线后拉取
- FR-02.3 已读回执：接收方确认消息已读，发送方可见已读状态
- FR-02.4 消息撤回：发送方在 2 分钟内可撤回已发送的消息
- FR-02.5 消息去重：基于 clientMsgId 实现幂等，防止重复发送
- FR-02.6 多设备同步：同一账号多设备同时在线时，所有设备均收到消息

**WebSocket 消息格式**：
```json
{
  "type": "message",
  "toUserId": 12345,
  "msgType": 1,
  "content": "Hello",
  "clientMsgId": "optional-client-id"
}
```

### FR-03 群聊消息

**描述**：多个用户在群组内进行消息通信。

**功能点**：
- FR-03.1 创建群组：指定群名称和初始成员列表
- FR-03.2 邀请入群：群成员邀请其他用户加入群组
- FR-03.3 退出群组：群成员主动退出
- FR-03.4 发送群消息：群成员向群内发送消息，所有在线成员实时接收
- FR-03.5 群消息扇出：小群（≤500人）采用写扩散，大群（>500人）采用读扩散
- FR-03.6 群消息序号：每条群消息分配递增 groupSeq，用于客户端同步
- FR-03.7 群消息撤回：与私聊撤回规则一致

**接口**：
- `POST /api/v1/relation/group/create`
- `POST /api/v1/relation/group/{groupId}/invite`
- `POST /api/v1/relation/group/{groupId}/quit`

### FR-04 消息可靠性

**描述**：保证消息从发送到接收的全链路可靠性，不丢失消息。

**功能点**：
- FR-04.1 至少一次投递：通过 Kafka + Outbox 双重保障，确保消息至少被投递一次
- FR-04.2 Outbox 兜底：跨实例消息通过 Outbox 表记录，定时扫描重试发布到 Kafka
- FR-04.3 Pending 索引表：非分片的 outbox_pending 表作为轮询索引，避免扫描 512 张分片表
- FR-04.4 Redis Reconcile 补偿：Outbox Pending 写入失败时，通过 Redis 哈希暂存，定时补偿
- FR-04.5 离线消息拉取：用户上线后通过 HTTP 接口拉取离线期间的消息
- FR-04.6 增量同步：客户端基于 conversationSeq/groupSeq 游标进行增量同步

**接口**：
- `GET /api/v1/message/offline`
- `POST /api/v1/message/sync`

### FR-05 连接管理

**描述**：管理客户端与服务端之间的 WebSocket 长连接。

**功能点**：
- FR-05.1 WebSocket 连接：客户端通过 `ws://host:8081/ws` 建立 WebSocket 连接
- FR-05.2 认证握手：连接建立后发送 auth 消息携带 JWT Token 完成认证
- FR-05.3 心跳保活：客户端每 30 秒发送心跳，服务端 300 秒无心跳则断开连接
- FR-05.4 设备踢旧：同一用户同一设备在新连接建立时，旧连接被主动关闭
- FR-05.5 路由表维护：认证成功后写入 Redis 路由表，心跳时续期
- FR-05.6 断线重连：客户端自动重连（最多 5 次，间隔 3 秒）

**WebSocket 消息类型**：
- `auth`：认证
- `heartbeat`：心跳
- `message`：消息收发
- `ack`：已读回执
- `recall`：消息撤回

### FR-06 文件传输

**描述**：支持图片、文件等富媒体消息的传输。

**功能点**：
- FR-06.1 文件上传：通过 MinIO 对象存储上传文件
- FR-06.2 预签名 URL：生成带时效的预签名 URL 供客户端直接上传/下载
- FR-06.3 文件元数据：记录文件名、大小、MIME 类型等元数据到数据库
- FR-06.4 降级控制：L4 降级时禁用文件上传功能

**接口**：
- `POST /api/v1/file/upload`
- `GET /api/v1/file/{fileId}/download`

### FR-07 在线状态

**描述**：实时展示好友的在线/离线状态。

**功能点**：
- FR-07.1 上线通知：用户上线时，广播在线状态给所有好友
- FR-07.2 下线通知：用户下线时，广播离线状态给所有好友
- FR-07.3 跨实例同步：通过 Kafka im-presence Topic 同步多实例间的在线状态
- FR-07.4 降级控制：L1 降级时关闭在线状态广播

### FR-08 消息搜索与历史

**描述**：支持历史消息查询和搜索。

**功能点**：
- FR-08.1 私聊历史：分页查询两个用户之间的历史消息
- FR-08.2 群聊历史：分页查询群组内的历史消息
- FR-08.3 消息搜索：按关键词搜索消息内容
- FR-08.4 消息上下文：获取某条消息的上下文消息
- FR-08.5 会话列表：获取用户的所有会话摘要（最近消息、未读数）

**接口**：
- `GET /api/v1/message/history/private`
- `GET /api/v1/message/history/group`
- `POST /api/v1/message/search`
- `POST /api/v1/message/context`
- `GET /api/v1/message/conversations`

### FR-09 好友关系

**描述**：管理用户之间的好友关系。

**功能点**：
- FR-09.1 发送好友申请
- FR-09.2 接受/拒绝好友申请
- FR-09.3 删除好友
- FR-09.4 查询好友列表

**接口**：
- `POST /api/v1/relation/friend/request`
- `POST /api/v1/relation/friend/accept`
- `POST /api/v1/relation/friend/reject`
- `DELETE /api/v1/relation/friend/{friendId}`
- `GET /api/v1/relation/friend/list`

### FR-10 服务降级

**描述**：在高负载或组件故障时，通过分级降级保障核心功能可用。

**功能点**：
- FR-10.1 L0 正常模式：所有功能可用
- FR-10.2 L1 关闭在线广播：停止好友在线状态推送，减少 Redis 和 Kafka 压力
- FR-10.3 L2 关闭已读回执：停止已读回执处理，减少数据库写入
- FR-10.4 L3 关闭大群推送：大群仅走读扩散，停止写扩散推送
- FR-10.5 L4 关闭文件上传：禁用文件/图片上传，仅保留文本消息
- FR-10.6 L5 仅文本模式：所有辅助功能关闭，仅保留文本消息收发

**接口**：
- `GET /admin/degradation`：查询当前降级状态
- `POST /admin/degradation/level/{level}`：设置降级等级

## 3 非功能需求

### NFR-01 性能

| 指标 | 目标值 |
|------|--------|
| 并发连接数 | ≥ 5,000 |
| 私聊吞吐量 | ≥ 5,000 msg/s |
| 群聊吞吐量 | ≥ 2,000 msg/s |
| WebSocket 连接 P95 延迟 | < 10ms |
| 消息发送 P99 延迟 | < 10ms |
| E2E 投递 P50 延迟 | < 100ms |
| E2E 投递 P99 延迟 | < 500ms |

### NFR-02 可靠性

| 指标 | 目标值 |
|------|--------|
| 消息投递率 | ≥ 99.9% |
| 消息丢失率 | < 0.1% |
| Outbox 重试成功率 | ≥ 99% |
| 服务可用性 | ≥ 99.9%（年停机 < 8.76h） |

### NFR-03 可用性

| 指标 | 目标值 |
|------|--------|
| 5 级降级策略 | 核心功能（文本消息）在任意降级等级下可用 |
| 单组件故障恢复 | Redis/Kafka 单节点故障后，通过降级保障核心功能 |
| 断线重连 | 客户端自动重连，重连后消息不丢失 |

### NFR-04 可扩展性

| 指标 | 目标值 |
|------|--------|
| 数据库分片 | 8 分片 × 64 表 = 512 张消息表，按用户 ID 和月份路由 |
| 水平扩展 | 支持多实例部署，通过 Redis 路由表 + Kafka Consumer Group 实例隔离 |
| K8s 部署 | 提供 Deployment + HPA + ConfigMap 配置 |

### NFR-05 安全性

| 指标 | 目标值 |
|------|--------|
| 传输安全 | WebSocket 支持 WSS |
| 认证 | JWT Token 认证，AccessToken 2h 过期 |
| 限流 | 用户级 500 msg/s，群组级 300 msg/s |
| 内部接口 | InternalAuthInterceptor 共享密钥保护 |

## 4 约束与假设

### 4.1 约束

- C-01：单机房部署，不涉及跨地域复制
- C-02：Kafka 单 Broker，不配置多副本
- C-03：Redis 单节点，不配置哨兵或集群
- C-04：MySQL 主从未配置，单主写入

### 4.2 假设

- A-01：用户在线率峰值不超过总注册用户的 20%
- A-02：单条消息大小不超过 64KB
- A-03：群组成员上限为 5,000 人
- A-04：消息撤回窗口为 2 分钟
- A-05：客户端心跳间隔为 30 秒
